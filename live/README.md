# Tap Duel Live

真人主持、攝影機讀牌的示範系統。一個小伺服器加三個網頁：

| 網頁 | 誰用 | 做什麼 |
|---|---|---|
| `/play.html` | 觀眾（手機） | 看牌桌畫面、在倒數內選擇、看結果與走勢 |
| `/host.html` | 主持人（iPad） | 開始回合、看讀到的牌、手動修正、確認結果或取消 |
| `/reader.html` | 讀牌器（架在牌桌上方的手機） | 讀牌、把結果與牌桌畫面傳給伺服器 |
| `/demo.html` | 想先看看的人 | 示範模式：三個畫面並排，不需要伺服器 |

兩款遊戲：

- **對決**：紅方、藍方各一張，點數大的勝。
- **九點**：藍方、紅方各兩到三張，總和個位數越接近 9 越好，固定規則決定是否補第三張，主持台會提示下一張該發哪個位置。押注有藍方、紅方、平手、兩方對子。

點數只是示範用：每位觀眾從 10,000 點開始，低於 1,000 可以補充。

## 示範模式：不用伺服器，用 GitHub Pages 就能玩

在 GitHub Pages 網址（或任何網址後面加 `?demo`）打開時，伺服器改在瀏覽器裡執行，跑的是同一份遊戲引擎（`public/engine.js`）。

- **`demo.html`**：觀眾、主持台、讀牌器三個畫面並排在同一頁。讀牌器用模擬攝影機，截止後自動把牌放到該出牌的位置並辨識。另有 5 位示範觀眾隨機參與。手機上會變成分頁切換。
- 也可以單獨開 `play.html`、`host.html`、`reader.html`：同一個瀏覽器的分頁共用一份資料（瀏覽器要支援 SharedWorker；不支援時每個分頁各自獨立，左下角會標示）。
- 示範模式不需要工作人員密碼，資料只在這個瀏覽器裡，重新整理 `demo.html` 就重新開始。
- 讀牌器在示範模式也可以按「開始相機」用真的相機與真的牌（GitHub Pages 是 HTTPS），但只有同一個瀏覽器裡的頁面看得到結果。

## 本機執行

```bash
cd live
npm install
STAFF_KEY=自己定一組密碼 npm start
# 打開 http://localhost:8080
```

沒設 `STAFF_KEY` 時，伺服器會產生一組並印在 log 裡。設 `DEMO_VIEWERS=5` 可以在正式伺服器上也加入最多 8 位隨機參與的示範觀眾（預設 0）。主持台與讀牌器要輸入這組密碼；也可以用 `host.html#key=密碼` 開一次，之後就記在那台裝置上。

讀牌器要開相機，瀏覽器只允許 HTTPS 或 `localhost`，所以實機測試請用部署後的網址。

## 部署到 Cloud Run

完整步驟（含密碼、權限、確認、更新、刪除與常見問題）見 **[DEPLOY.md](DEPLOY.md)**。重點：

- **一定要 `--max-instances 1`**：狀態全在記憶體，開兩個執行個體會各跑各的回合。
- **一定要 `--concurrency 1000`**：每位觀眾都佔一條連線，預設上限只有 80。
- `--min-instances 1` 避免縮到零而歸零，但會持續計費；重新部署也會歸零。

## 讀牌器的設定流程

**不用登記牌組，也不用拍空桌。**

1. 手機架在牌桌正上方，鏡頭朝下。桌面顏色要和牌有明顯差別（深色桌墊最好），避免反光。
2. 打開 `/reader.html`，選遊戲，按「開始相機」。
3. **調整牌位**：在畫面上拖曳框框對準桌上每個牌位。框要比牌大一圈，四邊都看得到桌面（桌面顏色是從框的邊緣即時量的）。
4. 用畫面上方的 **－／＋ 縮放**，讓牌位佔滿畫面。手機支援時用的是相機本身的變焦（不損畫質，有廣角鏡頭的手機還能縮到 1× 以下）；不支援時改為放大畫面中央。
5. 回到「運行」。畫面上的**牌高建議 240px 以上**，低於 150px 的讀數一律不採用；太小會提示把手機拉近。對決只有兩個牌位，牌可以排得很大；九點有六個牌位，手機要盡量靠近、讓牌位佔滿畫面。

換遊戲只要換桌墊、在讀牌器選另一款、調整牌位。

## 螢幕常亮

主持台與讀牌器會要求瀏覽器保持螢幕常亮（Screen Wake Lock，需要 HTTPS）。切到別的 App 或手動鎖定後，瀏覽器會收回常亮，回到頁面時會自動再要求；被拒絕時點一下畫面就會再試。沒有常亮時，主持台會出現黃色提示，讀牌器的狀態列也會顯示。

裝置上仍建議：接上電源、自動鎖定設成「永不」（iPhone／iPad：設定 → 螢幕顯示與亮度 → 自動鎖定；Android：顯示 → 螢幕自動關閉），並用引導使用模式（iOS）或螢幕固定（Android）把畫面鎖在瀏覽器，避免被誤觸切走。

**可以先放牌背**：倒數期間就能把牌背面朝上放進牌位，讀牌器會認出是牌背，主持台與觀眾都顯示一張蓋著的牌，不會跳警告。到了出牌階段再翻開，讀牌器會自動重讀。牌背不算已出牌；倒數期間就翻成正面的牌會提醒主持人，而且不會記錄點數。

主持台與觀眾看到的牌桌畫面就是讀牌器處理的畫面（含縮放），直放的手機會以直式完整顯示。

## 一個回合怎麼走

1. 主持台按「開始新回合」，觀眾倒數內選擇（預設 15 秒）。
2. 倒數結束後還有一段等待（預設 3 秒），用來蓋過直播的延遲。主持台畫面變綠「可以出牌」才翻牌。
3. 主持人把牌依序放進牌位，讀牌器讀到就出現在主持台上，顯示「光學 93%」與截圖。認不出來的會標紅，點那個牌位手動選。手動選的牌不會被攝影機蓋掉。
4. 九點會依規則提示要不要補第三張；不該出現的牌會被拒絕並提醒。
5. 牌到齊後按「確認結果」，伺服器結算並把點數發回觀眾。出錯就按兩次「取消回合」，全部退回。

6. **結算後要先收牌**：讀牌器還看得到正面朝上的牌時，主持台會提示「請先收掉桌上的牌：紅方、藍方」，主按鈕變成「桌上還有牌，先收掉」，自動開局也會等到收乾淨。原因是舊牌留在桌上，新回合一到出牌階段就會被讀成新的牌。牌背朝上的牌不擋（那是先放好的下一回合的牌）。讀牌器誤判時，主按鈕連按兩次可以強制開始。

主持台的主按鈕可以用 Enter、PageDown 或右方向鍵觸發，藍牙簡報器也能用。

## 光學辨識怎麼做

不用模型、不用外部函式庫、不用事先認識這副牌，全部在讀牌器的瀏覽器裡跑（`public/recognizer.js` 找牌、`public/ocr.js` 讀牌）：

1. **找牌**：每一格畫面都從牌位邊緣量出桌面的顏色，跟它不同的區域就是牌（桌面自己的陰影除外：只是等比例變暗的地方不算），量出中心、大小與角度。光線慢慢變化不受影響。
2. **切出牌角的字**：把牌轉正，在左上角找出墨跡（跟紙的顏色差得多的地方，任何顏色的印刷都算），最上面那一塊是點數（兩塊並排就是 10），正下方那一塊是花色。牌的邊框、裝飾線、被切到的圖案會被排除。
3. **比形狀**：把切出來的字形拉成固定大小，跟內建的樣板比——13 個點數各用 5 種字體、粗細兩種畫出來；4 種花色用幾何形狀與字體符號畫出來。字形會被拉伸，所以窄體、寬體字都適用。**花色只看形狀、不看顏色**，青綠色方塊或四色牌都一樣讀。
4. **把握度**：只看兩個最像的候選之間不同的地方，差距夠大才算清楚。花色另外量輪廓：頂端圓鈍的不會是黑桃、頂端尖的不會是梅花、頂端兩個圓弧的只會是紅心；輪廓和比對結果矛盾時不採用。淺色印刷（例如淡青色的花色）會用較低的門檻再切一次，取比較清楚的那次。
5. **三重確認**：左上角與右下角各自讀，必須一致；連續讀三格畫面，至少兩格有把握且結果相同才採用；沒把握就換新畫面重讀，最多三輪。
6. 仍沒把握就標成「認不出來」交給主持人，選牌視窗會列出最可能的三張。

測試結果（`test/ocr.test.js`）：

- **兩張真牌**（從手機截圖裁下的 J♦、10♦，窄體字、青綠色方塊）：都直接讀對。
- **四張真的 A**（手機拍的照片，淺褐色桌面，牌的一部分在陰影裡）：牌高 430px 以上四張都讀對；316px 與 230px 時 ♣A 交給人工，其餘讀對，沒有讀錯。
- **合成牌**，五種牌組（標準、青綠方塊、四色、襯線字、等寬字），隨機位置、傾斜 ±5°、正放倒放，共 1,040 次：

| 畫面中的牌高 | 直接讀對 | 交給人工 | 錯了卻有把握 |
|---|---|---|---|
| 200px | 75–88% | 12–25% | 0 |
| 280px | 95–100% | 0–5% | 0 |

- **真的 ♣2**（桌墊受光不均、旁邊露出白色桌面）：框得剛好或把白色桌面一起框進去，都讀對，不會被當成牌背。
- **其他桌面顏色**（各 52 張、牌高 300px）：米白 46、淺灰 52、中灰 52、淺褐 52、黑 51。純白桌面不支援（牌和桌面之間沒有邊界）。

**回歸底線**：`test/ocr.test.js` 對整組合成牌設了總分下限（200px 440／520、280px 510／520）、每種桌面的下限，以及所有真牌案例。為了修某一張牌而讓整體變差的改動會讓測試失敗。

真牌目前驗證過 J♦、10♦、四張 A、♣2，其餘要實測。牌角的字越大、越清楚越準；牌角沒有標準點數加花色的特殊牌組讀不到。主持人每回合確認一次，是最後一道防線。

```bash

npm run test:e2e           # 啟動伺服器，瀏覽器跑完整回合，最後一回合由讀牌器頁面看合成攝影機畫面

npm run test:all           # 以上全部
```

## 這個 prototype 沒有做的

- **觀眾的影像**只有讀牌器每 0.7 秒傳一張的低畫質照片；正式的直播影像仍然走直播平台。
- 沒有帳號，觀眾以瀏覽器裡的隨機 ID 識別；點數不能兌換。
- 狀態只在記憶體，重開就歸零；只能一個執行個體。
- 沒有接 UGPP 或任何錢包。
