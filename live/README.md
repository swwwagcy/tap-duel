# Tap Duel Live

真人主持、攝影機讀牌的示範系統。一個小伺服器加三個網頁：

| 網頁 | 誰用 | 做什麼 |
|---|---|---|
| `/play.html` | 觀眾（手機） | 看牌桌畫面、在倒數內選擇、看結果與走勢 |
| `/host.html` | 主持人（iPad） | 開始回合、看讀到的牌、手動修正、確認結果或取消 |
| `/reader.html` | 讀牌器（架在牌桌上方的手機） | 讀牌、把結果與牌桌畫面傳給伺服器 |
| `/demo.html` | 想先看看的人 | 示範模式：三個畫面並排，不需要伺服器 |

兩款遊戲：

- **對決**：紅方、藍方各一張，點數大的勝。
- **九點**：藍方、紅方各兩到三張，總和個位數越接近 9 越好，固定規則決定是否補第三張，主持台會提示下一張該發哪個位置。押注有藍方、紅方、平手、兩方對子。

點數只是示範用：每位觀眾從 10,000 點開始，低於 1,000 可以補充。

## 示範模式：不用伺服器，用 GitHub Pages 就能玩

在 GitHub Pages 網址（或任何網址後面加 `?demo`）打開時，伺服器改在瀏覽器裡執行，跑的是同一份遊戲引擎（`public/engine.js`）。

- **`demo.html`**：觀眾、主持台、讀牌器三個畫面並排在同一頁。讀牌器用模擬攝影機，自動拍空桌、用模擬牌登記 52 張，截止後自動把牌放到該出牌的位置並辨識。另有 5 位示範觀眾隨機參與。手機上會變成分頁切換。
- 也可以單獨開 `play.html`、`host.html`、`reader.html`：同一個瀏覽器的分頁共用一份資料（瀏覽器要支援 SharedWorker；不支援時每個分頁各自獨立，左下角會標示）。
- 示範模式不需要工作人員密碼，資料只在這個瀏覽器裡，重新整理 `demo.html` 就重新開始。
- 讀牌器在示範模式也可以按「開始相機」用真的相機與真的牌（GitHub Pages 是 HTTPS），但只有同一個瀏覽器裡的頁面看得到結果。

## 本機執行

```bash
cd live
npm install
STAFF_KEY=自己定一組密碼 npm start
# 打開 http://localhost:8080
```

沒設 `STAFF_KEY` 時，伺服器會產生一組並印在 log 裡。設 `DEMO_VIEWERS=5` 可以在正式伺服器上也加入最多 8 位隨機參與的示範觀眾（預設 0）。主持台與讀牌器要輸入這組密碼；也可以用 `host.html#key=密碼` 開一次，之後就記在那台裝置上。

讀牌器要開相機，瀏覽器只允許 HTTPS 或 `localhost`，所以實機測試請用部署後的網址。

## 部署到 Cloud Run

完整步驟（含密碼、權限、確認、更新、刪除與常見問題）見 **[DEPLOY.md](DEPLOY.md)**。重點：

- **一定要 `--max-instances 1`**：狀態全在記憶體，開兩個執行個體會各跑各的回合。
- **一定要 `--concurrency 1000`**：每位觀眾都佔一條連線，預設上限只有 80。
- `--min-instances 1` 避免縮到零而歸零，但會持續計費；重新部署也會歸零。

## 讀牌器的設定流程

1. 手機架在牌桌正上方 30–40 公分，鏡頭朝下。**桌面要比牌暗**（深色桌墊），燈光要穩定、避免反光。
2. 打開 `/reader.html`，選遊戲，按「開始相機」。
3. **調整牌位**：在畫面上拖曳框框，對準桌上每個牌位，框比牌大一圈。
4. 清空桌面，按「**拍空桌**」。相機或燈光動過就要重拍。
5. 回到「**運行**」就能開始。畫面上的牌高要在 **120px 以上**，太小會提示把手機拉近。
6. **登記牌組是選用的**：
   - 不登記也能用：每張牌由主持台手選（讀牌器有猜測時，選牌視窗會列出前三名）。手選的結果不會被讀牌器記住。
   - 登記完整的牌組後就會自動讀牌：到「登記牌組」把 52 張依序放一次，同一副牌兩款遊戲共用。
   - 只登記一部分時，讀牌器即使有把握也只當建議、不自動填入：它只能在登記過的牌裡挑最像的，沒登記的牌會被硬配到別張。每個點數登記過兩種花色、每種花色登記過六個點數後，才開始自動讀牌。

換遊戲只要換桌墊、在讀牌器選另一款、調整牌位並重拍空桌，已經學會的牌不用重新登記。

## 螢幕常亮

主持台與讀牌器會要求瀏覽器保持螢幕常亮（Screen Wake Lock，需要 HTTPS）。切到別的 App 或手動鎖定後，瀏覽器會收回常亮，回到頁面時會自動再要求；被拒絕時點一下畫面就會再試。沒有常亮時，主持台會出現黃色提示，讀牌器的狀態列也會顯示。

裝置上仍建議：接上電源、自動鎖定設成「永不」（iPhone／iPad：設定 → 螢幕顯示與亮度 → 自動鎖定；Android：顯示 → 螢幕自動關閉），並用引導使用模式（iOS）或螢幕固定（Android）把畫面鎖在瀏覽器，避免被誤觸切走。

## 一個回合怎麼走

1. 主持台按「開始新回合」，觀眾倒數內選擇（預設 15 秒）。
2. 倒數結束後還有一段等待（預設 3 秒），用來蓋過直播的延遲。主持台畫面變綠「可以出牌」才翻牌。
3. 主持人把牌依序放進牌位，讀牌器讀到就出現在主持台上，顯示「光學 97%」與截圖。認不出來的會標紅，點那個牌位手動選。手動選的牌不會被攝影機蓋掉。
4. 九點會依規則提示要不要補第三張；不該出現的牌會被拒絕並提醒。
5. 牌到齊後按「確認結果」，伺服器結算並把點數發回觀眾。出錯就按兩次「取消回合」，全部退回。

主持台的主按鈕可以用 Enter、PageDown 或右方向鍵觸發，藍牙簡報器也能用。

## 光學辨識怎麼做

不用模型、不用外部函式庫，全部在讀牌器的瀏覽器裡跑（`public/recognizer.js`）：

1. 跟空桌比較，找出牌位裡比桌面亮的區域，量出牌的中心、大小與角度（不受陰影影響）。
2. 把牌轉正，取左上角的點數花色。
3. 跟登記時拍的 52 張範本比較。點數與花色**分開**判斷，各自用從範本學到的權重：在不同點數之間差異大的像素用來判斷點數，花色同理，所以不用告訴它牌角在哪，任何牌款都適用。
4. 只看兩個最像的候選之間不同的像素，算出分離程度。
5. **左上角與右下角各自判斷，必須一致**，連續三格畫面平均後才下結論。
6. 不夠有把握就回報「認不出來」，交給主持人手選。

合成牌的測試結果（`test/recognizer.test.js`，隨機位置、傾斜 ±5°、倒放、亮度與雜訊）：

| 畫面中的牌高 | 有把握且正確 | 交給人工 | 錯了卻有把握 |
|---|---|---|---|
| 90px（太小，不建議） | 約 70% | 約 28% | 偶有 1–3 次 |
| 130px | 約 89% | 約 11% | 0 |
| 160px | 約 90% | 約 10% | 0 |

**這是合成牌的數字，真實的牌、燈光與手機鏡頭一定要實測。** 主持人每回合確認一次，是最後一道防線。

## 測試

```bash
npm test                   # 兩款遊戲的規則與點數計算
npm run test:recognizer    # 光學辨識準確度（合成牌）
node test/light-table.test.js   # 淺色桌面（牌只比桌面亮一點）
node test/colour-deck.test.js   # 方塊印成青綠色的牌組：顏色檢查要自動停用
npm run test:e2e           # 啟動伺服器，瀏覽器跑完整回合，最後一回合由讀牌器頁面看合成攝影機畫面
npm run test:demo          # 只用靜態檔案（像 GitHub Pages）跑示範模式的兩款遊戲與分頁共用
npm run test:all           # 以上全部
```

## 這個 prototype 沒有做的

- **觀眾的影像**只有讀牌器每 0.7 秒傳一張的低畫質照片；正式的直播影像仍然走直播平台。
- 沒有帳號，觀眾以瀏覽器裡的隨機 ID 識別；點數不能兌換。
- 狀態只在記憶體，重開就歸零；只能一個執行個體。
- 沒有接 UGPP 或任何錢包。
